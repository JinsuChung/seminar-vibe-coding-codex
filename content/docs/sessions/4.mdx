## 개념

### 로컬 도구에서 서비스로

- 2회차의 HTML 도구는 **내 PC에서만** 열립니다. 동료가 쓰려면 파일을 메일로 보내야 하고, 고칠 때마다 다시 보내야 합니다.
- 서버에 올리면 **주소 하나로 누구나 같은 최신 버전**을 씁니다. 이것이 <Term id="deploy">배포</Term>입니다.
- <Term id="vercel">Vercel</Term>은 GitHub 저장소를 연결해 두면 **푸시할 때마다 자동으로 다시 배포**합니다. 3회차의 커밋·푸시가 곧 업데이트 버튼이 됩니다.

### 기술 용어는 딱 세 개만

| 용어 | 뜻 |
| --- | --- |
| <Term id="nextjs">Next.js</Term> | 웹앱의 뼈대(<Term id="framework">프레임워크</Term>). 구조는 Codex가 만들고 사람이 확인한다 |
| <Term id="localhost">localhost</Term> | 내 PC에서만 열리는 시험용 주소. 배포 전 확인용 |
| <Term id="env">환경변수</Term> | 비밀번호·키처럼 코드에 적으면 안 되는 값을 따로 보관하는 칸. 5–6회차에서 본격 사용 |

### Vercel 무료 요금제 — 꼭 알아야 할 것

- 무료(Hobby) 요금제: <Fact k="vercel.hobby" />. 교육·시제품에는 충분합니다.
- 요금제 조건은 바뀔 수 있습니다. 회사의 정식 업무 서비스로 운영하기 전 [Vercel 공식 요금 문서](https://vercel.com/pricing)를 확인하고 사내 IT·보안 기준을 검토합니다.
- 배포 주소는 기본적으로 **누구나** 열 수 있습니다. 내부용이면 Vercel Authentication(무료 포함)으로 접근을 제한하거나, 개인정보를 넣지 않습니다.

| 구분 | 로컬 HTML (2회차) | 배포한 웹앱 (4회차) |
| --- | --- | --- |
| 누가 쓰나 | 나, 또는 파일을 받은 사람 | 주소를 아는 누구나 |
| 업데이트 | 파일을 다시 보내야 함 | 푸시하면 자동 반영 |
| 휴대폰 | 어려움 | 바로 열림 |
| 주의할 점 | 거의 없음 | 공개 범위, 개인정보, 요금제 조건 |
