## 시작하며

"최종.hwp", "최종_수정.hwp", "최종_진짜최종_v3.hwp"… 이런 파일 이름을 만들어 본 적 있나요? 오늘은 그 문제를 제대로 푸는 도구를 배웁니다.

## 개념

### 왜 AI와 일할수록 버전 관리가 필수인가

- AI는 한 번에 여러 파일을 빠르게 고칩니다. 잘되던 기능이 다른 요청 때문에 깨지는 일이 흔합니다.
- Claude Code에도 되돌리기(`/rewind`)가 있지만, 공식 문서도 "Git을 대신하지 않는다"고 밝힙니다. 명령으로 바뀐 파일이나 다른 사람과의 공유는 추적하지 못합니다 ([Best practices](https://code.claude.com/docs/en/best-practices)).
- 바이브 코딩과 에이전틱 엔지니어링을 가르는 **첫 번째 안전장치**가 바로 이것입니다.

### 핵심 개념 4가지

| 개념 | 뜻 | 행정 비유 |
| --- | --- | --- |
| <Term id="repository">저장소</Term> (repository) | 변경 이력을 기록하는 폴더 | 문서대장이 붙은 서류철 |
| <Term id="commit">커밋</Term> (commit) | 지금 상태를 메모와 함께 저장하는 세이브 포인트 | 결재 버전 + 변경 사유 |
| <Term id="push">푸시</Term> (push) | 내 PC의 이력을 GitHub에 올리기 | 기록물실 이관 |
| <Term id="gitignore">.gitignore</Term> | 올리지 말 파일 목록 | 대외비 분류 |

아래에서 직접 커밋하고, 망가뜨리고, 되살려 보세요.

<Callout type="warn" title=".gitignore가 중요해지는 이유">
  4–6회차에서는 비밀번호·API 키가 담긴 `.env` 파일이 생깁니다. 이 파일을 GitHub에 올리는 것이 **가장 흔한 보안 사고**입니다. 저장소를 처음 만들 때부터 .gitignore에 넣어 두세요.
</Callout>

**브랜치와 풀 리퀘스트**는 "원본을 건드리지 않고 시험하는 사본" 정도로만 알아 두면 됩니다. 심화 실습에서 한 번 체험합니다.

### 말로 하는 Git — 외울 필요 없는 문장들

| 하고 싶은 것 | Claude Code에게 하는 말 |
| --- | --- |
| 시작 | `이 폴더를 Git 저장소로 만들고, 올리면 안 되는 파일은 .gitignore에 넣어줘` |
| 저장 | `지금까지 바뀐 내용을 한글 메시지로 커밋해줘` |
| 확인 | `커밋 이력을 날짜와 함께 표로 보여줘` |
| 비교 | `마지막 커밋 이후 뭐가 바뀌었는지 쉽게 설명해줘` |
| 되돌리기 | `어제 커밋 상태로 파일을 되돌려줘. 지금 상태는 따로 보관하고` |
| 업로드 | `GitHub에 비공개 저장소를 만들고 올려줘` |

<Callout title="습관 하나만 남긴다면">
  **잘 돌아갈 때마다 커밋.** "기능 하나 완성 = 커밋 하나"를 CLAUDE.md에 규칙으로 적어 두면 Claude가 알아서 챙깁니다.
</Callout>
