## 개념

### 바이브 코딩의 탄생

2025년 2월 2일, OpenAI 공동창업자 **안드레이 카파시**가 X(옛 트위터)에 새로운 코딩 방식을 소개했습니다. 코드가 있다는 사실조차 잊고 "분위기(vibe)에 몸을 맡기는" 코딩, 바로 **<Term id="vibe-coding">바이브 코딩</Term>**입니다 ([원문](https://x.com/karpathy/status/1886192184808149383)).

이 말은 그해 콜린스 사전 **올해의 단어(2025)**로 뽑혔습니다 ([Wikipedia](https://en.wikipedia.org/wiki/Vibe_coding)). 의미는 간단합니다. **코드를 모르는 사람도 말로 설명해서 소프트웨어를 만들 수 있게 됐다**는 것입니다.

<Analogy title="행정 업무로 비유하면">
  예전에는 프로그램 하나를 만들려면 기획서 → 예산 → 외주·전산팀 → 수개월이 필요했습니다. 이제는 업무 지시를 하듯 말로 설명하면 몇 분 안에 동작하는 도구가 나옵니다.
</Analogy>

### 그런데 바이브만으로는 사고가 난다

"알아서 해줘"로만 맡기면 문제가 생깁니다. 실제로 있었던 일입니다.

| 시기 | 사건 | 교훈 |
| --- | --- | --- |
| 2025년 5월 | 한 바이브 코딩 플랫폼으로 만든 웹앱 1,645개 중 170개에서 개인정보 노출 취약점 발견 | 만든 뒤 **보안 점검**을 건너뛰었다 |
| 2025년 7월 | 한 AI 코딩 서비스가 "변경 금지" 지시에도 사용자의 운영 데이터베이스를 삭제 | AI에게 **되돌릴 수 없는 권한**을 줬다 |

출처: [Wikipedia — Vibe coding](https://en.wikipedia.org/wiki/Vibe_coding)

만드는 것은 AI가 해도, **무엇을 만들지 정하고 결과를 확인하는 것은 사람의 몫**입니다.

### 에이전틱 엔지니어링

카파시는 2026년 4월 세콰이아 어센트에서 이렇게 정리했습니다. "바이브 코딩은 바닥을 올리고, 에이전틱 엔지니어링은 천장을 올린다" ([요약 기사](https://www.aibuilderclub.com/blog/karpathy-agentic-engineering)).

**<Term id="agentic-engineering">에이전틱 엔지니어링</Term>**은 AI 에이전트가 계획·작성·테스트를 하고, 사람은 **요구사항 정의 → 계획 검토 → 결과 검증**을 맡는 일하는 방식입니다.

| 구분 | 바이브 코딩 | 에이전틱 엔지니어링 |
| --- | --- | --- |
| 태도 | "알아서 해줘" | "이렇게 해줘, 그리고 확인할게" |
| 시작 | 바로 만들기 | 계획 먼저 보기 (플랜 모드) |
| 안전장치 | 없음 | 버전 관리(Git), 검증 기준, 권한 승인 |
| 어울리는 일 | 나만 쓰는 일회용 도구 | 동료가 쓰는 도구, 배포하는 서비스 |

<Callout type="info" title="사무직 관점으로 번역하면">
  우리가 이미 잘하는 일입니다. **기획서 쓰기, 업무 지시하기, 결과물 검토하기.** 실무 역량이 곧 개발 역량이 되는 시대입니다. 이 과정의 1–2회차는 작은 자동화로 시작하고, 3회차부터 안전장치를 하나씩 더합니다.
</Callout>

### 인스턴트 소프트웨어의 시대

벤처캐피털 a16z의 아니시 아차르야는 2025년 8월 이렇게 썼습니다. 소프트웨어를 만들지 말지는 그동안 **투자 대비 효과**가 결정했지만, 이제는 **상상력**만이 한계라고요 ([Disposable Software](https://a16z.com/disposable-software/)).

<Term id="instant-software">인스턴트 소프트웨어</Term>는 필요할 때 말로 만들어 쓰고, 필요 없으면 지우는 작은 도구입니다. 모두 "프로그램까지 만들 일은 아니던" 일입니다. 이제는 10분이면 만들고, 다 쓰면 지워도 됩니다.

### 챗봇과 에이전트는 무엇이 다른가

| | 챗봇 (웹 채팅) | 에이전트 (Codex 앱) |
| --- | --- | --- |
| 파일 | 내가 올리고, 답을 복사해 내가 저장 | **내 컴퓨터 폴더를 직접 열어 읽고 씀** |
| 실행 | 내가 직접 | 프로그램을 실행하고 결과를 확인 |
| 반복 | 틀리면 내가 다시 질문 | 스스로 확인하고 고침 |
| 사람의 역할 | 손발 | **지시하고 승인하기** |

아래에서 같은 일을 두 방식으로 시켜 보세요.

<Sim name="chat-vs-agent" />

에이전트는 중요한 행동(파일 수정, 명령 실행) 전에 **권한을 묻습니다**. 이 승인 버튼이 우리의 첫 번째 안전장치입니다. 플랜 모드를 켜면 아예 계획만 세우고 멈춥니다.

</Callout>

## 왜 ChatGPT Codex 앱으로 배우나요

한 문장으로 답하면 이렇습니다. **기획서를 쓰는 대화와 프로그램을 만드는 대화가 끊기지 않고, 그 두 가지를 모두 최상위 수준으로 해내는 도구**이기 때문입니다.

### 기획과 개발이 한 사람, 한 대화 안에서

- **예전:** 기획자가 문서로 설명 → 개발자가 해석 → 결과물이 생각과 다름 → 재수정. 번역 손실이 크다
- **지금:** 업무를 가장 잘 아는 사람이 직접 만들고, 쓰면서 바로 고친다. **기획서가 곧 설계도**다

Codex 앱에서는 같은 작업 공간에서 기획 문서를 쓰고, 코드를 만들고, 실행 결과를 확인할 수 있습니다.

| 순서 | 내가 하는 말 (예) | 하는 일 | 남는 것 |
| --- | --- | --- | --- |
| 1 | "매주 업무 요청 정리가 너무 오래 걸려. 같이 생각해 보자" | **채팅** — 문제 정리, 아이디어 | 대화 |
| 2 | "필요한 걸 질문해서 기획서.md로 정리해줘" | **기획 문서** — 요구사항, 범위, 검증 기준 | `기획서.md` |
| 3 | "기획서대로 공고 PDF에서 마감 일정표를 만드는 도구를 만들어줘" | **코드** — 프로그램 작성 | 도구 파일 |
| 4 | "실습 폴더로 돌려 보고 기획서 요구사항을 다 지켰는지 표로 보여줘" | **실행·검증** — 직접 돌려 보고 확인 | 결과 파일, 검증표 |
| 5 | "팀장님께 보고할 1쪽 요약을 써줘" | **문서** — 보고서 | `보고.md` |
| 6 | "마감 7일 전 알림도 넣자. 기획서도 같이 고쳐줘" | **기획 ↔ 코드** 함께 수정 | 고쳐진 기획서와 도구 |

이 과정 전체가 이 흐름을 연습합니다. 1회차는 1번, 2회차는 2–4번, 4–6회차는 6번을 웹·데이터·AI로 넓혀 가는 셈입니다.

### 다른 도구와 무엇이 다른가

AI 도구는 크게 네 종류입니다. 모두 좋은 도구이고 기능이 빠르게 늘고 있어서, 아래 표는 2026년 10월 기준 **일반적인 특징**입니다.

| 구분 | 웹 채팅 | 앱 빌더 | 개발자 편집기 | **ChatGPT Codex 앱** |
| --- | --- | --- | --- | --- |
| 주 사용자 | 누구나 | 웹앱을 빠르게 만들려는 사람 | 개발자 | **기획자부터 개발자까지** |
| 내 PC 파일 직접 다루기 | 올린 파일만 | 주로 클라우드 안에서 | 코드 폴더 중심 | **업무 폴더 전체** (엑셀·PDF·워드·사진) |
| 기획 문서 쓰기 | 잘함 (복사해서 저장) | 앱 설명 위주 | 가능하지만 코드 중심 | **잘함, 파일로 바로 저장** |
| 코드 작성·실행·검증 | 코드만 보여 줌 | 웹앱 위주로 잘함 | 잘함 | **잘함, 직접 실행하고 확인** |
| 웹앱이 아닌 작은 도구 (엑셀 취합, 파일 정리) | 어려움 | 어려움 | 가능 | **잘함** |
| 시작 장벽 | 가장 낮음 | 낮음 | 개발 지식 필요 | 낮음 (데스크톱 앱) |

<Analogy title="사내 업무에 빗대면">
  웹 채팅은 <b>전화 상담</b>, 앱 빌더는 <b>외주 제작사</b>, 개발자 편집기는 <b>개발팀 장비</b>에 가깝습니다. Codex 앱은 작업 폴더에서 문서와 코드를 다루는 <b>신입 동료</b>와 같습니다. 중요한 변경은 사람이 승인하고 검증합니다.
</Analogy>

### 기획 문서도, 코드도 최상위 성능

이 과정의 핵심은 **같은 AI가 기획 문서와 코드를 둘 다 잘해야** 한다는 점입니다. 기획서는 잘 쓰는데 코드가 약하거나, 코드는 잘 짜는데 문서가 어색하면 결국 둘 사이를 사람이 다시 번역해야 하기 때문입니다.

| 확인할 영역 | 실습에서 볼 기준 |
| --- | --- |
| **코드** | 요청한 기능이 동작하고 테스트를 통과하는가 |
| **문서** | 원문의 숫자와 출처를 유지하고 사내 문체를 따르는가 |
| **실무 사용** | 파일 범위, 승인 지점, 결과 검증이 명확한가 |

모델 성능과 제공 모델 이름은 수시로 바뀝니다. 수업 직전 [OpenAI 모델 문서](https://platform.openai.com/docs/models)와 [Codex 공식 문서](https://developers.openai.com/codex/)를 확인하세요.

<Callout type="info" title="숫자보다 중요한 것">
  모델 이름과 성능 순위는 빠르게 바뀝니다. 특정 순위보다 <b>우리 업무의 가상 사례로 정확도·속도·비용을 직접 검증</b>하는 것이 중요합니다.
</Callout>

### 이 과정이 Codex 앱을 고른 이유 정리

- **기획 ↔ 코딩 ↔ 채팅을 오가는 하나의 작업 공간** — 기획서·코드·보고서가 같은 폴더, 같은 대화에 남는다
- **업무 파일을 직접 다룸** — 엑셀·PDF·워드·사진이 가득한 행정 업무에 맞는다
- **안전장치를 문서화** — 권한 승인, 계획 검토, Git, AGENTS.md
- **터미널 없이 시작** — 데스크톱 앱의 Code 탭
- **끝까지 이어짐** — 내 PC 도구(1–2회차)에서 배포·데이터베이스·AI 기능(4–6회차)까지 같은 도구로

솔직한 한계도 있습니다. **유료(Pro 이상)**이고, 대화 내용이 AI 모델로 **전송**되며, 결과는 언제나 **사람이 검증**해야 합니다. 6회차에서 안전하게 쓰는 원칙을 자세히 다룹니다.

## 시연

강사가 같은 요청을 웹 채팅과 Codex 앱에 각각 보내 차이를 보여 줍니다.

<Steps>
<FdStep>
**웹 채팅에** "이 폴더 파일들을 업무별로 정리하는 방법 알려줘" → 방법만 알려 주고, 파일 목록은 사람이 붙여 넣어야 함
</FdStep>
<FdStep>
**Codex 앱에** 같은 요청 → 폴더를 직접 열어 파일 40개를 읽고, 이름만으로는 알 수 없는 파일까지 내용을 확인해 부서별 분류 계획을 표로 제시
</FdStep>
<FdStep>
**계획 승인** → 실제로 폴더가 생기고 파일이 옮겨지는 것을 파일 탐색기에서 함께 확인
</FdStep>
</Steps>

</FdStep>
<FdStep>
ChatGPT Codex 앱에서 **폴더 선택** → `사내_공유폴더_정리전`을 엽니다. 이 폴더 밖의 파일은 작업 범위에 넣지 않습니다.
</FdStep>
</Steps>
