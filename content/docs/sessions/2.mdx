## 개념

### 4단계 작업법

Codex로 여러 파일을 다룰 때는 **바로 만들게 하지 말고 탐색과 계획을 분리**합니다. 그래야 엉뚱한 문제를 풀거나 원본을 덮어쓰는 일을 막습니다.

| 단계 | AI가 하는 일 | 사람이 하는 일 | 모드 |
| --- | --- | --- | --- |
| 1. 탐색 | 파일을 읽고 상황 파악 | 무엇을 볼지 알려 주기 | 플랜 모드 |
| 2. 계획 | 어떻게 할지 제안 | **검토하고 고치고 승인** | 플랜 모드 |
| 3. 실행 | 파일 만들고 고치기 | 권한 승인 | 일반 모드 |
| 4. 검증 | 기준대로 스스로 확인 | **결과 확인** | 일반 모드 |

강조된 두 칸, 계획 승인과 결과 확인이 사람이 책임지는 자리입니다.

- **<Term id="plan-mode">플랜 모드</Term>** — 파일을 읽기만 하고 고치지 않는 모드. 터미널에서는 <Kbd keys="shift+tab" />, 데스크톱 앱에서는 입력창의 모드 메뉴에서 고릅니다.
- 한 문장으로 설명되는 작은 일(오탈자 수정 등)은 계획 없이 바로 시켜도 됩니다.
- **검증이 핵심입니다.** "합계가 원본과 맞는지 검산해서 보여줘"처럼 확인할 기준을 주면, AI가 틀린 부분을 스스로 찾아 고칩니다.

### 업무 프롬프트 5요소

기안문에 목적·근거·내용·붙임이 있듯이, 업무 지시에도 빠지면 안 되는 요소가 있습니다.

| 요소 | 질문 | 예시 |
| --- | --- | --- |
| 목적 | 왜 하는가? | 월말 과제별 집행률 보고용 |
| 입력 | 무엇을 가지고? | `집행내역` 폴더의 엑셀 10개 |
| 출력 | 무엇을 만들어? | 과제별 합계 표 1개, 엑셀 파일 |
| 조건 | 지켜야 할 것은? | 원본은 절대 수정 금지, 금액은 원 단위 쉼표 |
| 검증 | 맞는지 어떻게 아나? | 파일별 합계와 총합을 대조해 보여줄 것 |

### 인터뷰형 기획: AI가 나에게 질문하게 하기

큰 작업은 거꾸로 AI에게 질문을 받습니다. 기획자가 현업 담당자를 인터뷰하던 일을 AI가 나에게 해 주는 셈입니다.

<PromptCard id="interview-spec" />

<Analogy title="인터뷰형 기획이 좋은 이유">
  "매달 파일 개수가 바뀌나요?", "합계가 안 맞으면 어떻게 표시할까요?" 같은 질문은 막상 만들기 전에는 떠오르지 않습니다. 질문에 답하다 보면 기획서가 완성되고, 그 기획서가 곧 설계도가 됩니다.
</Analogy>

### AGENTS.md — AI에게 주는 업무 인수인계서

폴더에 `AGENTS.md` 파일을 두면 Codex가 작업할 때 프로젝트 규칙으로 참고합니다. **짧게, 매번 필요한 것만** 씁니다. 적용 범위와 우선순위 등 현재 동작은 [OpenAI AGENTS.md 공식 문서](https://developers.openai.com/codex/guides/agents-md/)를 확인하세요.

```markdown title="AGENTS.md 예시"
# 사내 업무 규칙
- 모든 답변과 파일은 한국어로
- 원본 파일은 절대 수정하지 말고, 결과물은 '결과' 폴더에 새로 만들 것
- 날짜는 YYYY-MM-DD, 금액은 원 단위 천 단위 쉼표
- 파일을 삭제하거나 이동하기 전에는 변경 목록을 먼저 보여줄 것
```

<PromptCard title="AGENTS.md 만들기" text="이 폴더의 반복 업무 규칙을 질문으로 확인한 뒤 AGENTS.md 초안을 만들어줘. 원본 보호, 결과 폴더, 날짜·금액 형식, 삭제 전 승인 규칙을 포함하고 짧게 써줘." />

| 넣을 것 | 뺄 것 |
| --- | --- |
| 매번 지켜야 할 규칙 (원본 보호, 날짜 형식) | AI가 파일을 보면 알 수 있는 것 |
| 우리 팀만의 약속 (폴더 이름, 파일명 규칙) | 자주 바뀌는 정보 |
| 자주 하는 실수와 주의점 | 길고 일반적인 설명 |

### 자주 쓰는 조작 4가지

| 조작 | 하는 일 |
| --- | --- |
| <Kbd keys="esc" /> | 작업 중 멈추기 (대화는 유지) |
| <Kbd keys="esc" /> 두 번 또는 `/rewind` | 이전 시점으로 되돌리기 (파일까지) |
| `/clear` | 주제가 바뀔 때 대화 초기화 |
| `@파일명` | 특정 파일을 직접 가리키기. 스크린샷은 끌어다 놓기 |

<Callout type="warn" title="같은 실수를 두 번 넘게 고쳤다면">
  대화에 실패한 시도가 쌓인 상태입니다. `/clear`로 비우고, 배운 점을 넣어 더 구체적인 요청으로 새로 시작하는 편이 빠릅니다.
</Callout>
