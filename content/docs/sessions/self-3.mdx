## 1일차 Git은 무엇을 기록하나

<KeyPoints
  items={[
    '커밋은 세이브 포인트, 푸시는 클라우드 백업. 명령어는 Codex가, 판단은 내가.',
    '저장소는 기본 비공개(private). 업무 자료가 든 저장소를 공개로 만들지 않는다.',
    '.env 같은 비밀 파일은 처음부터 .gitignore에. 실수로 올렸다면 키를 재발급한다.',
  ]}
/>

<DeepDive title="커밋 하나에 담기는 것">

커밋은 "파일 복사본"이 아니라 **바뀐 부분 + 누가 + 언제 + 왜**를 묶은 기록입니다.

| 담기는 것 | 예 | 행정 비유 |
| --- | --- | --- |
| 바뀐 내용 | `출장비계산기.html` 3줄 수정 | 수정 대비표 |
| 메시지 | "광역시 숙박 상한 8만 원으로 변경" | 변경 사유 |
| 작성자·시각 | 홍길동, 2026-10-22 14:05 | 기안자·기안일 |
| 이전 커밋 연결 | 바로 앞 세이브 포인트 | 문서 이력 번호 |

그래서 파일 이름을 `최종_수정_v3`처럼 바꿀 필요가 없습니다. 파일은 하나로 두고, **이력은 Git이** 관리합니다.

</DeepDive>

<DeepDive title="얼마나 자주 커밋할까">

**"잘 돌아갈 때마다, 기능 하나마다"**가 기준입니다.

| 너무 드묾 | 적당함 | 너무 잦음 |
| --- | --- | --- |
| 하루 일을 커밋 하나에 | 기능 하나 완성 = 커밋 하나 | 글자 하나 고칠 때마다 |
| 되돌릴 때 좋은 부분까지 같이 사라짐 | 원하는 지점으로 정확히 돌아감 | 이력이 너무 길어 찾기 어려움 |

AGENTS.md에 "기능 하나를 마치면 한글 메시지로 커밋"이라고 적어 둡니다.

</DeepDive>

## 3일차 되돌리는 세 가지 방법

<DeepDive title="상황별로 다른 되돌리기">

| 상황 | 방법 | 이렇게 말하기 |
| --- | --- | --- |
| 방금 대화에서 한 작업이 마음에 안 듦 | 앱의 되돌리기 기능 | 현재 화면의 되돌리기 동작을 확인 |
| 며칠 전 잘되던 상태로 통째로 | 커밋으로 되돌리기 | "어제 커밋 상태로 되돌려줘. 지금 상태는 따로 보관하고" |
| 다른 건 두고 파일 하나만 | 특정 파일만 되돌리기 | "사용법.txt만 마지막 커밋 상태로 되돌려줘" |

"지금 상태는 따로 보관하고"를 붙이면 되돌린 것을 다시 되돌릴 수도 있습니다.

</DeepDive>
