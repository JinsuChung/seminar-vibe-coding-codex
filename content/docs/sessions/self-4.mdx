<DeepDive title="공모 보드 폴더 들여다보기">

4회차 완성본을 압축 풀면 이런 파일이 있습니다. 전부 외울 필요는 없고, **어디를 고치면 무엇이 바뀌는지**만 알면 됩니다.

| 파일 | 하는 일 | 고치면 바뀌는 것 |
| --- | --- | --- |
| `data/grants.ts` | 공모 목록 데이터 | 보드에 보이는 공모 |
| `app/page.tsx` | 첫 화면 (카드 목록, D-day 계산) | 화면 구성, 정렬, 표시 방식 |
| `app/globals.css` | 색·글꼴·간격 | 디자인 |
| `app/layout.tsx` | 모든 페이지 공통 틀, 브라우저 탭 제목 | 사이트 이름 |
| `package.json` | 필요한 부품 목록과 실행 명령 | (거의 안 고침) |
| `CLAUDE.md` | AI 작업 규칙 | AI의 행동 |

직접 확인해 보세요.

<PromptCard title="구조 설명 듣기" text="이 웹앱의 폴더 구조를 비개발자가 알아듣게 설명해줘. 공모 데이터를 바꾸려면 어느 파일을, 디자인을 바꾸려면 어느 파일을 고치면 되는지도 알려줘." compact />

</DeepDive>

<DeepDive title="localhost와 배포 주소, 무엇이 다른가">

| | localhost (내 PC) | ….vercel.app (배포) |
| --- | --- | --- |
| 누가 보나 | 나만 | 주소를 아는 누구나 |
| 언제 바뀌나 | 파일을 저장하는 즉시 | 커밋·푸시 후 1~2분 |
| 용도 | 고치면서 확인 | 동료와 공유 |
| 꺼지면 | 내 PC나 개발 서버를 끄면 안 열림 | 항상 열림 |

그래서 순서는 언제나 **localhost에서 확인 → 커밋·푸시 → 배포 주소에서 다시 확인**입니다.

</DeepDive>

<DeepDive title="Vercel 대시보드, 여기만 알면 된다">

| 메뉴 | 위치 | 쓰는 때 |
| --- | --- | --- |
| **Deployments** | 프로젝트 상단 탭 | 배포 목록. 푸시할 때마다 한 줄씩 생김. 문제가 생기면 예전 배포를 골라 **Promote**로 되돌릴 수 있음 |
| **Build Logs** | 배포 하나 클릭 | 빌드 실패 원인. 빨간 줄을 복사해 Claude Code에 |
| **Domains** | Settings → Domains | 주소 바꾸기 (예: `syu-grant-board.vercel.app`) |
| **Deployment Protection** | Settings → Deployment Protection | **Vercel Authentication**을 켜면 로그인한 사람만 볼 수 있음 |
| **Environment Variables** | Settings → Environment Variables | 5·6회차에서 키를 넣는 곳 |

</DeepDive>
